# Browser reply engine

The browser version uses the same localized reply pools as the native bot.
[`replies.generated.js`](replies.generated.js) is generated by running the
**compiled Lean executable**, once for every valid index in each language's
pool. Reply text is not copied into a separate hand-written JavaScript catalog.

## Generate and verify the catalog

With Python 3.11+ and the repository's pinned Lean toolchain available:

```sh
python scripts/export_web.py
python scripts/export_web.py --check
```

Run these commands from the repository root. Both build the current Lean source
first, then invoke `indeed-core catalog` to learn the locales and pool sizes.
Every exported phrase is obtained separately through
`indeed-core reply <locale> <index>` and checked against the native catalog.
The current export covers **50 selections across 10 languages**.

`--check` fails if the committed module differs from the current compiled core
or its recorded source provenance. It does not rewrite the module. CI should run
it after the Lean proof audit; the export parity test also checks every native
selection against the committed module:

```sh
python scripts/check_axioms.py
python scripts/export_web.py --check
uv run pytest tests/test_web_export.py
```

The exporter needs only Python's standard library. It does not run language
detection, download models, or require an API key.

## Module interface

```js
import { replyCatalog, catalogMetadata } from './replies.generated.js';
```

- `replyCatalog` maps each locale code to its ordered array of reply strings.
  The object and each array are frozen to prevent accidental edits at runtime.
- `catalogMetadata` records the schema version, package version, pinned Lean
  toolchain, source hashes, catalog hash, and locale/reply counts.

Source hashes cover `lean/Indeed.lean`, `lean/Main.lean`, and
`lean/lean-toolchain`. The catalog checksum is SHA-256 over UTF-8 JSON with sorted
keys, no ASCII escaping, and compact separators. No build timestamp, machine
path, or platform-specific executable hash appears in the export, so identical
inputs produce identical module bytes across machines.

## What the proof covers

Lean proves that `Indeed.selectReply` returns a nonempty member of the selected
locale's pool and is deterministic for a given locale and draw. The native
executable calls that function directly. The exporter enumerates its finite
selection space and tests that every exported entry matches the executable.

The browser samples an index and reads this exported data. **The JavaScript
selector and the browser application are not formally verified.** Exporting
proof-checked native results does not constitute a proof of the exporter,
language detector, browser randomness, JavaScript execution, bundler, deployment,
or the meaning or truth of a reply. Source-hash metadata provides traceability;
it is not a cryptographic signature or a proof certificate.

No Lean runtime is shipped to the browser. This static catalog preserves the
native bot's available replies without a server or a duplicate hand-maintained
phrase list. See [`lean/README.md`](../lean/README.md) for the exact native theorem
names and assumptions.

## Build and use the browser runtime

Install Node.js 22 or newer, then run from the repository root:

```sh
npm ci
npm run build:web
npm run test:web
```

The build writes a self-contained ES module to `web/dist/engine.js`, with the
full dependency license text in `web/dist/THIRD_PARTY_NOTICES.txt`. Publish both
files together with this repository's `LICENSE`. The bundle has no external
imports and makes no requests when selecting a reply.

```js
import { reply, supportedLanguages, maxInputLength } from './engine.js';

const answer = reply('这个想法值得一试。');
// { text: <a Chinese agreement>, language: 'zh', index: <pool index>, detection: ... }
const inFrench = reply('An ambitious idea.', { language: 'fr' });
```

`reply(text, { language: 'auto' })` returns a synchronous result. The language
option accepts `auto` or one of the ten keys in `supportedLanguages`. It rejects
blank inputs, unsupported language overrides, and strings longer than
`maxInputLength` (8,000 UTF-16 code units). The runtime does not retain input.

Automatic detection uses Unicode scripts, common greetings and word evidence,
then Franc for supported Latin-script languages. It is a browser implementation,
not the terminal's Python Lingua detector; short, mixed, and unsupported inputs
can be ambiguous. When evidence is insufficient, it falls back to English.
`detection.source` identifies `script`, `lexicon`, `franc`, `fallback`, or
`override`; these are routing decisions, not calibrated confidence scores.

Selection uses Web Crypto with rejection sampling to avoid modulo bias. The
runtime throws if secure randomness is unavailable. Tests cover all ten
languages, explicit overrides, input validation, ambiguous cases, random-number
boundaries, catalog membership, and importing the actual bundled module.

The live chat UI is maintained in the
[Indeed Lab website repository](https://github.com/indeed-lab/indeed-lab.github.io).
That repository pins the bot source commit and artifact hashes when it vendors a
release of this engine.
